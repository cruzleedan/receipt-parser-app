## Problem

Location at review commit `813e330`: `src/llm_service.py:179-181; src/gemini_service.py:201-203`.

Both non-VLM prompts request only up to ten products, although `items=true` advertises line-item extraction with no such API limit. A longer grocery receipt is intentionally incomplete even if the model follows instructions perfectly, and the response carries no truncation indication. This also interacts with the small fallback output budget.

## Decision

Implemented: Remove the hidden product limit and define an explicit long-receipt policy with sufficient token budgeting, chunking, or an incompleteness signal understood by callers. Reuse the policy in all backends.

- [x] Output-token exhaustion cannot be mistaken for a complete receipt.
